# Atrium: architecture and code guide

This guide describes Atrium's architecture and the rules every change follows.

Atrium is a modular, Folia-native server essentials plugin for Paper/Folia 26.1.2+ (Java 25, Gradle Kotlin DSL).
Package root: `dev.yanianz.atrium`. Its feature scope is comparable to the CMI plugin, built from scratch with a
modern design. All paths below are relative to the repository root.

## Clean-room rule (mandatory)
- Atrium is an independent implementation. Do not copy code from other plugins, whether from source, decompilation or otherwise.
- Public documentation and observed behaviour of other plugins may be used to understand which features exist;
  the implementation must be your own.
- Do not add code under a license that conflicts with Atrium's license (see `LICENSE` and `NOTICE`).

## Layout
| Path | What |
|---|---|
| `atrium-api/` | Public API for other plugins: `Atrium.api()`, `UserService`, `ServiceRegistry`, service interfaces (`economy`, `teleport`, ...) |
| `atrium-core/` | Framework: `Scheduler` (Folia), `Cmds`/`CommandSpec` (Brigadier), `ConfigService`, `Messages` (MiniMessage i18n), `Database` (+`Migration`), `UserManager`, `ModuleManager`, menu toolkit |
| `modules/<name>/` | One feature module per directory, auto-included by `settings.gradle.kts` and bundled by `atrium-plugin` |
| `modules/player/` | **Reference module**. Copy its structure. |
| `atrium-plugin/` | Assembles the final jar and `paper-plugin.yml`. Change it only when a change requires it. |
| `atrium-vault/` | Atrium Vault, the separate drop-in Vault/VaultUnlocked plugin (bundles the LGPL VaultAPI v1 and VaultUnlockedAPI v2 classes unmodified) |
| `compat/sourbyapi-26.2/` | Compile-only SourbyCraft API baseline, downloaded and hash-checked at build time |
| `buildSrc/` | Shared Gradle conventions (`atrium.module`, `atrium.java-conventions`) |
| `scripts/` | `new-server.sh` (isolated test server), `smoke.sh` (boot a server, run console commands) |
| `docs/` | User documentation; `COMMANDS.md` and `PERMISSIONS.md` are generated by `/atrium docs` |

## Writing a module
1. `modules/<name>/build.gradle.kts` with `plugins { id("atrium.module") }`.
2. Class `dev.yanianz.atrium.module.<name>.<Name>Module implements AtriumModule`, listed in
   `src/main/resources/META-INF/services/dev.yanianz.atrium.core.module.AtriumModule`.
3. Everything goes through `ModuleContext`: `config(...)`, `migrate(...)`, `command(...)`, `listen(...)`,
   `track(task)`, `service(...)`, `component(...)`, `permission(...)`. These are undone automatically on disable.
4. Messages: `src/main/resources/lang/<module>/en_US.yml` **and** `id_ID.yml` (same keys). Keys are
   used as `<module>.<key>`. Start player-facing lines with `<prefix>`. An empty string disables a message.
5. Config: one `@ConfigSerializable` class with `@Comment` on every option → `plugins/Atrium/modules/<module>.yml`.
6. Storage: own tables named `{prefix}<module>_<thing>` created by `Migration`s (never edit a released
   migration; add a new version). Per-player data = a `UserComponentType` with an immutable record value.
7. Cross-module contracts: put interfaces in `atrium-api/src/main/java/dev/yanianz/atrium/api/<area>/`.
   Prefer new files; changing an existing API type is a breaking change for other plugins. Publish with
   `ctx.service(...)`, consume with `ctx.services().get(...)` (optional dependency) or declare `dependencies()`.

## Core APIs worth knowing
- `users().resolveAccount(name, includeNeverJoined)` → `PlayerRef` (online → known → profile lookup). Use it for any command
  that accepts an offline player name. `Cmds.knownPlayers(users())` gives online+offline name suggestions.
- `users().saveNow(uuid)` → future; confirm a change to the player only after it completes.
- `users().accountsByAddress(ip)`, `AtriumUser.lastAddress()` for alt checks / seen.
- `ctx.cooldowns()`: persisted per-player cooldowns (`tryAcquire(user, "<module>:<key>", duration)` is atomic).
- `ctx.track(task)` is thread-safe and drops finished tasks: track every timer you start.
- Services published so far (atrium-api): economy `EconomyService`; teleport `TeleportService` (+`ExtendedTeleportService`);
  warps `WarpService`, `WarpAdminService`; homes `HomeService`; rtp `RandomTeleportService`; moderation `MuteService`,
  `PunishmentService`; chat `ChatGate`, `IgnoreService`; vanish `VanishService`; afk `AfkService`; playtime
  `PlaytimeService`, `PlaytimeAdminService`; ranks `RankService`; worth `WorthService`; actions `ActionService` (run
  admin-defined action lines safely); holograms `HologramService`; nick `NickService`; player `FlightService`
  (claim-based flight: never toggle `allowFlight` directly); proxy `ProxyService` (authenticated cross-server topics).
  Consume optional ones with `ctx.services().get(...)`.
- Generated reference: `/atrium docs` writes `plugins/Atrium/docs/COMMANDS.md` and `PERMISSIONS.md`. Copy them to
  `docs/` when commands or permissions change.
- **Theme tags:** in lang files use `<primary>`, `<secondary>`, `<accent>`, `<muted>`, `<success>`, `<warning>`,
  `<error>`, `<highlight>` instead of raw colours (palette in `config.yml` → `theme`, applied on `/atrium reload`).
  Typical line: `"<prefix><success>Home <highlight><home></highlight> set."`. Per-call placeholders win over theme tags of
  the same name; `Msg.unparsed` text is never parsed. `messages().theme()` / `globalTags()` for custom parsing.
- **Menus:** use `ctx.menus()` (`dev.yanianz.atrium.core.menu.MenuService`) for any GUI; never a raw `Bukkit.createInventory`
  + click listener. `Menu.builder(title, rows).item(slot, ItemBuilder.of(mat).name(..).lore(..).build(), click -> ...)`,
  `PagedMenu.builder(menus, title).content(viewer -> buttons)`, `menus.confirm(...)`, `click.open/replace/back/close`.
  Every click/drag is cancelled unless the slot is declared with `.input(...)`; handlers run on the viewer's thread,
  debounced; menus close on quit/world change/module disable. Nav labels: `core.menu.*`.
- `/atrium help [page|module]` and `/atrium menu` list what the sender may use from `CommandService.entries()`:
  give every `CommandSpec` a real description.

## Rules that prevent common plugin bugs
- **Threads (Folia):** never use `Bukkit.getScheduler()`/`BukkitRunnable`. Touch an entity/player only on
  its own thread: `scheduler().entity(...)`/`supplyOnEntity(...)`; blocks via `region(...)`/`supplyAt(...)`;
  world-independent state via `global(...)`. Storage/HTTP only via `Database`/`supplyIo`. Commands run on the
  sender's thread, so a target player must be handled through `scheduler().entity(target, ...)`.
- **Teleport** only with `teleportAsync`.
- **Other players:** every command that can target someone else uses `cmds.selfOrOther(...)` or checks a
  `.others` permission explicitly. Offline targets go through `users().load(...)`/`loadByName(...)`.
- **Untrusted text** (chat, names, sign/anvil/book text, command args) is inserted with
  `Msg.unparsed(...)`, never parsed as MiniMessage and never fed to PlaceholderAPI.
- **Money/items:** compute what is actually removed/added, then pay for exactly that. Never pay first and
  remove later; never trust a stale snapshot one tick later. Economy writes are single DB transactions.
- **Permissions with numbers** (`atrium.homes.5`) via `Permissions.limit(...)`: no caching.
- **Events:** call cancellable events *before* acting and honour cancellation; listen with
  `ignoreCancelled = true` unless there is a reason not to.
- **Failure:** never swallow exceptions silently; log with context. A failed save must not be reported as success.
- **Locale-safe formatting:** `String.format(Locale.ROOT, ...)` for anything persisted or parsed.
- **Proxy messages:** cross-server data goes through `ProxyService`, which authenticates every message (HMAC);
  never act on an unauthenticated plugin message.
- No NMS, no reflection into server internals, no `sun.*`. Use Paper API only.

## Build & test
- Build one module: `./gradlew :modules:<name>:build` · everything: `./gradlew build`.
- Offline build (no download of the SourbyCraft API sources): `./gradlew build -PsourbycraftRepo=/path/to/SourbyCraft`.
- Pure logic gets JUnit tests in `modules/<name>/src/test/java` (JUnit 6).
- Runtime check: put a Folia server jar at `run/folia/folia.jar` (the shared baseline; `run/` is not committed).
  Then `scripts/new-server.sh <name> <port>` once (pick a free port 25601–25699), and
  `./gradlew build && scripts/smoke.sh run/<name> "<console command>" ...`. It must print `SMOKE: OK`.
  Do not smoke-test in `run/folia` itself and do not run two smoke tests on the same directory.
- Keep a change within the module(s) it concerns, plus new API files. Do not commit or push unless asked to.
